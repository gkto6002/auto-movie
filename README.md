# auto-movie

自動/手動で短尺動画を作成し、YouTubeにアップロードするための計画・運用ガイドです。まずはアカウント/課金設定とプロンプト準備を行い、その後「手動アップロード方式」または「AWSを使った自動化システム」で運用します。


## 目的と前提
- 目的: 毎日定期的に動画を公開し、チャンネル運用を効率化する。
- 前提: OpenAI Sora（または同等の動画生成API）へのアクセス権があること。SoraのAPI公開状況や利用条件は変わる可能性があるため、最新のドキュメントに従ってください。


## 1. 事前準備（アカウント/課金/素材）

### アカウント設定（必須）
1) AWSアカウント設定
	 - AWSアカウント作成/ログイン
	 - 課金の有効化（クレジットカード登録）
	 - IAMユーザー作成（プログラムアクセス）と適切な権限付与
	 - AWS CLI の設定（macOS例）
		 ```zsh
		 brew install awscli
		 aws configure  # アクセスキー/シークレット/Region/出力形式を設定
		 ```

2) OpenAIアカウント設定
	 - OpenAIアカウント作成/ログイン
	 - 有料プランへのアップグレード（クレジットカード登録）
	 - APIキー発行（`OPENAI_API_KEY`）
	 - Sora（または動画生成機能）へのアクセスが必要な場合は申請/有効化

3) YouTubeアカウント設定
	 - Googleアカウント/YouTubeチャンネルの準備
	 - 課金が必要な場合に備えクレジットカード登録（Google側の必要に応じて）
	 - Google Cloud Console で YouTube Data API v3 を有効化
	 - OAuthクレデンシャル作成（クライアントID/シークレット）
	 - 手動でリフレッシュトークンを取得し、アップロード自動化で使用

### クレジットカード登録（まとめ）
- AWS: 課金有効化に必須。
- OpenAI: 有料プラン/トークン利用に必須。
- YouTube/Google: 必要に応じて（API利用そのものは基本無料だが、プロジェクト/課金設定が必要なことがあります）。

### プロンプト準備（31個）
- 31本分の動画プロンプトを事前に用意します（手動運用で30本生成＋予備1本）。
- 推奨フォーマット（例：JSON Lines）
	```json
	{ "id": 1, "title": "〇〇の豆知識", "prompt": "テーマAを60秒で解説。〜", "tags": ["shorts","education"] }
	{ "id": 2, "title": "△△の裏ワザ", "prompt": "テーマBを60秒で解説。〜", "tags": ["tips"] }
	```
- タイトル/説明/タグ/公開設定（公開/限定公開/予約）方針も合わせて決めておきます。

#### 運用ポリシー（番号固定でループ）
- 31個のプロンプトに連番（1〜31）を付与し、「日付に応じて固定の番号を使う」方式にします。
- 例: 月の日数に関わらず、`当日番号 = ((通算日数 - 1) mod 31) + 1` を用いて選択。
- この方式では「使用済み」フラグ管理は不要です。毎日決まったプロンプトが選ばれます。
- 祝日・不定期休止がある場合は、その日の公開をスキップするか、後日同番号を使う運用とします。


## 2. 手動アップロード方式

### 手順概要
1) 有料プランの Sora を用いて30本の動画を生成
	 - 先に用意した31プロンプトのうち30件を選び、バッチ生成。
	 - 画質/尺/アスペクト比はYouTube Shorts向け（例: 1080×1920, 60秒以内）を推奨。

2) YouTube への予約アップロード
	 - YouTube Studio で30本を一括または順次アップロード。
	 - タイトル/説明/タグ/サムネイルを設定。
	 - 公開スケジュールを設定（毎日同時刻など）。

### 補足
- 手動方式は初期構築が不要で確実ですが、運用の手間がかかります。
- 生成に失敗した場合の差し替え用として1本分の予備プロンプトを残しておくと安心です。


## 3. 自動化システム（AWS + OpenAI API + YouTube API）

### 使用技術
- AWS Lambda: 生成/アップロードの実行ロジック
- Amazon S3: 生成した動画の一時保管
- Amazon EventBridge: 毎日の定期実行トリガー
- OpenAI API: 動画生成（Sora 等）
- YouTube Data API v3: 動画アップロード

### 全体フロー（簡易）
1) 毎日 EventBridge が Lambda を起動
2) Lambda が用意済みプロンプトを1件取得（S3上の `prompts.jsonl` から「当日番号」に該当する行を選択）
3) OpenAI API（Sora）で動画生成（非同期ジョブの場合はポーリング/コールバックで完了待機）
4) 生成した動画を S3 に保存
5) YouTube API でチャンネルへアップロード（タイトル/説明/タグ/公開時刻を付与）
6) アップロード完了後、S3 から当該動画を削除
7) 当日番号の管理のみ（使用済みフラグは不要）

### アーキテクチャ例
- 単一Lambdaで一連の処理を実行（シンプル）
- 状態管理は最小限（`state.json` 不要）。日付から当日番号を計算して `prompts.jsonl` から選択
- 将来的に規模が増えたら Step Functions/DynamoDB の採用を検討

### 環境変数/シークレット（例）
- `OPENAI_API_KEY`: OpenAIのAPIキー（Sora等の利用に必須）
- `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`: OAuthクライアント情報
- `YOUTUBE_REFRESH_TOKEN`: オフラインアップロード用のリフレッシュトークン
- `S3_BUCKET`: 一時保管用バケット名
- `PROMPTS_S3_KEY`: プロンプトファイルのキー（例: `config/prompts.jsonl`）
- `AWS_REGION`: 実行リージョン

機微情報は AWS Secrets Manager に保管し、Lambda から参照する運用を推奨します。

### IAM 権限（最小権限の目安）
- Lambda 実行ロールに付与:
	- `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`（対象バケット/プレフィックス限定）
	- `secretsmanager:GetSecretValue`（必要なシークレットのみに限定）
	- `logs:CreateLogGroup`, `logs:CreateLogStream`, `logs:PutLogEvents`

### S3 バケット作成（例）
```zsh
aws s3api create-bucket \
	--bucket auto-movie-temp-<任意のユニーク名> \
	--region ap-northeast-1 \
	--create-bucket-configuration LocationConstraint=ap-northeast-1
```

### EventBridge での毎日実行（例）
- スケジュール式（毎日 09:00 JST 実行の例。UTC換算に注意）
	- JST 09:00 は UTC 00:00（サマータイム非考慮）
	- 例: `cron(0 0 * * ? *)`

### 実装の疑似フロー（単一Lambda）
```text
handler()
 ├─ 日付から「当日番号」を計算
 ├─ 当日番号に対応するプロンプトをS3から取得
 ├─ OpenAI(Sora)に動画生成リクエスト送信
 ├─ 生成完了までポーリング/待機
 ├─ 動画をS3へ保存
 ├─ YouTube APIでアップロード（メタ情報付与）
 ├─ S3から動画を削除
 └─ （使用済み管理は不要）
```

### 注意点
- SoraのAPI/仕様は変わる可能性があるため、最新のレート/クォータ/料金/生成時間を確認。
- YouTube API は OAuth2 を要し、サーバーレス環境でのトークン更新フロー設計が重要。
- コスト管理（OpenAIトークン/AWS/Lambda実行時間/S3転送料）を定期的に確認。


## 4. 運用手順クイックリファレンス

### 初期セットアップ
1) AWS/OPENAI/Youtube の各アカウント作成＋クレジットカード登録
2) YouTube Data API v3 を有効化、OAuth クライアント作成、リフレッシュトークン取得
3) `OPENAI_API_KEY` などのシークレットを AWS Secrets Manager に保存
4) S3 バケット作成、`prompts.jsonl` をアップロード
5) Lambda 関数をデプロイし、必要な環境変数/IAMを設定
6) EventBridge で毎日実行のスケジュールを作成

### 手動方式（短期運用）
1) Soraで30本生成 → ローカル保存
2) YouTube Studioで予約公開設定してアップロード

### 自動化方式（本運用）
1) 毎日1本（または任意本数）を自動生成→アップロード
2) 失敗時のリトライ/監視（CloudWatch Logs/アラーム）


## 5. 今後の拡張アイデア
- Step Functions で生成→アップロード→後処理を明確に分離
- DynamoDB でプロンプト使用状況/公開ステータスを厳密管理
- サムネイル自動生成（画像生成API）とA/Bテスト
- メタ情報（タイトル/タグ）の自動最適化
- マルチチャンネル対応
